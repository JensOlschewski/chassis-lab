# KnC Validation

Python tooling for comparing Adams/Car KnC simulations with physical KnC
measurements. This repository contains analysis code only. Model data,
measurements, and generated solver results remain outside this repository.

## Pipeline

```text
Adams model (.adm)
  -> event generation (adams-scripts)
  -> Adams solver (.res)
  -> conversion (adams-res-cli)
  -> normalized result (.h5)
  -> validation (this project)
  -> metrics, plots, and report
```

The initial reader supports HDF5 format version 3 generated by
[`adams-res-cli`](https://gitea.mariecolette.de/jens/adams-res-cli). The ADM
event generator remains an external, model-specific dependency in
`../adams-scripts`.

## Setup

```shell
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[dev]'
```

Inspect a converted Adams result:

```shell
.venv/bin/knc inspect-h5 /path/to/result.h5
.venv/bin/knc inspect-h5 /path/to/result.h5 --json
.venv/bin/knc list-h5-signals /path/to/result.h5 --match svc_output
```

Read only a required component column:

```python
from knc_validation.hdf5 import AdamsHdf5

with AdamsHdf5("result.h5") as result:
    wheel_load = result.read_signal(
        "til_wheel_tire_forces",
        "normal_front",
        expected_unit="newton",
    )

print(wheel_load.values)
```

The reader indexes signal metadata when the file is opened, but numerical
values are loaded only for requested entity/component pairs. A physical HDF5
path such as `/results/til_wheel_tire_forces_2` can explicitly disambiguate
duplicate Adams entity aliases when needed; mapping configuration should use
the stable Adams entity name instead.

Inspect and query a Lommel ACD measurement:

```shell
.venv/bin/knc inspect-acd /path/to/measurement.acd
.venv/bin/knc list-acd-signals /path/to/measurement.acd --match lfwcz
```

```python
from knc_validation.acd import AcdFile

measurement = AcdFile("measurement.acd")
signals = measurement.read_signals(("time", "lfwcz"))
wheel_travel = signals["lfwcz"]
```

The ACD reader detects the metadata boundary, encoding, channel order, units,
and offsets. It preserves `NaN` and `Inf`; domain evaluators decide whether
non-finite values are valid for channels they use.

## Configuration

Convert a `.res` result file to HDF5 and validate a case configuration:

```shell
.venv/bin/knc convert-res /path/to/result.res -o artifacts/svc/result.h5 \
    --binary /path/to/adams-res
.venv/bin/knc validate-config configs/varb-lommel-2up-svc.toml
```

A case TOML declares the case metadata, simulation input, and gravitational
constant. SVC cases inherit one shared canonical signal mapping from
`knc_validation.svc`, so VARB/VARC and loadcase files do not duplicate mappings:

```toml
[case]
name = "varb-lommel-2up-svc"
domain = "svc"
variant = "VARB"
loadcase = "2UP"

[inputs]
simulation_hdf5 = "../artifacts/varb-lommel-2up-svc/result.h5"

[physics]
gravity = 9.80665 # m/s^2
```

Paths in `[inputs]` are resolved relative to the configuration file, so runs
never depend on the current working directory. Signals whose entity shares a
source path with another axis (such as the rear wheel-tire forces) must be
pinned to their explicit `/results/<group>` path in `[signals]`.
`validate-config` re-checks every shared mapping against the HDF5 file when
present, including source units and duplicate-cell detection. It reports
`VERIFIED` for matching source metadata, `UNVERIFIED` when legacy HDF5 omits a
source unit but the configured physical unit is known, and `ERROR` for missing
signals or mismatched units. Add `--strict-units` to reject missing source
metadata.

Run development checks:

```shell
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/pytest
```

## Repository boundaries

- `adams-res-cli` owns `.res` parsing and the HDF5 format.
- `adams-scripts` owns generation of event-specific Adams input/control files.
- `knc-validation` owns measurement import, signal conventions, calculations,
  comparisons, plots, reports, and acceptance criteria.
- Source data is read-only. Generated files are written below `artifacts/` and
  are not committed.

See [`docs/architecture.md`](docs/architecture.md) for interfaces and
[`docs/roadmap.md`](docs/roadmap.md) for the migration plan.
